# 01 — Problem

## The problem

A prawn farmer has a pond and no way to act on what they are seeing. Four things go wrong in practice:

**Count.** "How many prawns do I have" is answered by pulling a net and counting by hand. It is slow, it disturbs the pond, and the number is wrong anyway by the time it matters.

**Water quality.** pH, TDS and temperature drift through the day. A farmer can only check them by wading in with a test kit, so they check them rarely and react late. The thresholds that matter (pH 7.0–8.5, TDS 1000–1500 ppm, 28–32 °C, as written into the Gemini prompt in `backend/gemini_service.py`) go unnoticed until prawns are visibly stressed.

**Disease.** White gut, loose shell and shell-loss show up on individual animals well before they show up in the pond. By the time a farmer can name the problem, it has spread.

**Advice.** Even with readings in hand, the question "what do I actually do" needs an aquaculture specialist, which is not available at pondside.

## Why the data has a hole

`backend/Prawndataset.csv` carries `Cannot Predict` in the `Prawn_Count` column for some rows. `backend/model.py` filters those out rather than imputing them:

```python
df = df[pd.to_numeric(df['Prawn_Count'], errors='coerce').notna()]
```

That is the honest reading — for those pond conditions the count genuinely was not recorded. But it means the model is trained only on the cases where someone did get a number, and it is asked at inference time to produce a number for conditions resembling the dropped ones. There is no confidence interval and no out-of-domain check on `/predict`.

## The failure this design tolerates

The app is built so that each piece degrades instead of failing:

- No serial port open → `sensor_service.py` returns mock pH 8.1 / TDS 1200 / 28.5 °C.
- Roboflow errors → `analyze_prawn_image` returns `"Error analyzing image"` with the exception string, and `main.py` still produces a report without the image section.
- Gemini errors or no API key → the PDF carries a one-line fallback asking the farmer to consult a specialist.

For a demo this is the right call. For a farmer acting on medication dosages generated by a language model, silently substituting plausible-looking mock readings is the dangerous failure, and nothing in the code marks those values as fake downstream.
